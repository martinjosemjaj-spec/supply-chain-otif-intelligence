# Rollback Guide — OTIF Guardian RC1

**Version:** 1.0.0-rc1  
**Prepared:** 2026-08-28  
**RTO Target:** < 5 minutes (full rollback)

---

## Rollback Principles

1. Each stage can be rolled back independently
2. Rollback executes in reverse deployment order (Stage 8 → Stage 1)
3. Partial rollback is supported (e.g., roll back only ML pipeline without touching bootstrap)
4. Data generation rollback destroys synthetic data (irreversible without re-running script)
5. Full rollback (`DROP DATABASE`) destroys everything — requires explicit approval

---

## Emergency Rollback (All Stages)

If a critical failure is detected post-deployment and full removal is required:

```sql
-- EMERGENCY: Execute only with explicit approval from Technical Lead
DROP DATABASE IF EXISTS OTIF_GUARDIAN;
DROP WAREHOUSE IF EXISTS OTIF_GUARDIAN_WH;
DROP RESOURCE MONITOR IF EXISTS OTIF_GUARDIAN_RM;
DROP ROLE IF EXISTS OTIF_GUARDIAN_APP;
DROP ROLE IF EXISTS OTIF_GUARDIAN_ANALYST;
DROP ROLE IF EXISTS OTIF_GUARDIAN_ENGINEER;
DROP ROLE IF EXISTS OTIF_GUARDIAN_ADMIN;
```

**Time to execute:** < 30 seconds  
**Time to re-deploy:** ~3 minutes (full pipeline)

## Rollback Decision Matrix

| Symptom | Rollback Scope | Stages Affected |
|---------|----------------|-----------------|
| Agent returning errors | Stage 8 only | Agent |
| Model accuracy unacceptable | Stages 5-8 | ML + Recovery + Procedures + Agent |
| Semantic view broken | Stages 4-8 | Semantic + ML + Recovery + Agent |
| Data integrity issues | Stages 2-8 | Everything except infrastructure |
| Security incident | Full teardown | All stages |
| Wrong environment deployed | Full teardown | All stages |
